# Especificación de Requisitos de Software (SRS v3.2 Final)
## Sistema de Control de Asistencias con Reconocimiento Facial

---

## 1. Introducción y Alcance
El objetivo es gestionar y automatizar el registro diario de asistencia del personal (marcado de **Entrada** y **Salida**) mediante verificación biométrica facial en un kiosco con cámara web en tiempo real.

La plataforma administra estructura organizacional (gerencias, roles, usuarios), horarios globales con trazabilidad histórica, feriados (día único o rango), vacaciones por empleado, pases previos fuera de margen, justificativos, horas extras, histórico clicable por empleado y auditoría total. Horario global único para toda la empresa. Días laborables lunes a viernes. Máximo 100 empleados.

## 2. Definición del Modelo de Datos (Base de Datos SQL)

### 2.1. Tablas

#### 1. `gerencias`
* `id` (INT, PK, AI)
* `nombre` (VARCHAR(100), UNIQUE, NOT NULL)
* `created_at` (TIMESTAMP, Default CURRENT_TIMESTAMP)

#### 2. `roles`
* `id` (INT, PK, AI)
* `nombre` (VARCHAR(50), UNIQUE, NOT NULL): `'ADMIN'`, `'RRHH'`, `'GERENTE'`, `'COORDINADOR'`.

#### 3. `usuarios`
Cuentas prediseñadas: por cada gerencia un `GERENTE` y un `COORDINADOR`, más globales `ADMIN` y `RRHH`.
* `id` (INT, PK, AI)
* `username` (VARCHAR(50), UNIQUE, NOT NULL)
* `password` (VARCHAR(255), NOT NULL, Bcrypt Cost >= 12)
* `rol_id` (INT, FK -> `roles.id`, NOT NULL)
* `gerencia_id` (INT, FK -> `gerencias.id`, NULLABLE): NULL para `ADMIN`/`RRHH`, obligatorio para `GERENTE`/`COORDINADOR`.
* `requiere_cambio_password` (BOOLEAN, Default TRUE)
* `activo` (BOOLEAN, Default TRUE)
* `created_at`, `updated_at` (TIMESTAMP)

#### 4. `empleados`
* `id` (INT, PK, AI)
* `cedula_dni` (VARCHAR(20), UNIQUE, NOT NULL)
* `nombre` (VARCHAR(100), NOT NULL)
* `apellido` (VARCHAR(100), NOT NULL)
* `cargo` (VARCHAR(100), NOT NULL)
* `gerencia_id` (INT, FK -> `gerencias.id`, NOT NULL)
* `face_descriptor` (JSON/TEXT, NOT NULL): vector 128 flotantes (`Float32Array`, `@vladmandic/face-api`).
* `activo` (BOOLEAN, Default TRUE): FALSE = no ficha en kiosco ni genera FALTA, conserva historial.
* `created_at` (TIMESTAMP)

#### 5. `reglas_asistencia` (global, una vigente a la vez)
* `id` (INT, PK, AI)
* `hora_limite_entrada` (TIME, NOT NULL)
* `hora_salida_referencia` (TIME, NOT NULL, Default '17:00')
* `margen_tardanza_min` (INT, NOT NULL, Default 60): minutos máximos para entrar como TARDE.
* `fecha_inicio_vigencia` (DATE, NOT NULL)
* `creado_por_usuario_id` (INT, FK -> `usuarios.id`, NOT NULL)
* `created_at` (TIMESTAMP)

#### 6. `asistencias` (una fila por empleado/día)
* `id` (INT, PK, AI)
* `empleado_id` (INT, FK -> `empleados.id`, NOT NULL)
* `fecha` (DATE, NOT NULL)
* `hora_llegada` (TIME, NULLABLE): NULL en justificativo por ausencia total.
* `hora_salida` (TIME, NULLABLE)
* `estado_entrada` (ENUM('A TIEMPO','TARDE','JUSTIFICADO'), NOT NULL)
* `estado_salida` (ENUM('COMPLETADO','TEMPRANO'), NULLABLE): COMPLETADO = salida >= referencia, TEMPRANO = salida < referencia.
* `regla_aplicada_id` (INT, FK -> `reglas_asistencia.id`, NULLABLE)
* `hora_limite_aplicada` (TIME, NULLABLE): snapshot entrada.
* `hora_salida_referencia_aplicada` (TIME, NULLABLE): snapshot salida.
* `horas_extras` (DECIMAL(4,2), Default 0): día normal = MAX(0, salida - referencia); día FERIADO/VACACIONES trabajado = salida - llegada.
* `url_justificativo` (VARCHAR(255), NULLABLE)
* `comentario_justificativo` (TEXT, NULLABLE)
* `justificado_por_usuario_id` (INT, FK -> `usuarios.id`, NULLABLE)
* `url_foto_fichaje` (VARCHAR(255), NULLABLE): thumbnail 150x150 solo si `GUARDAR_FOTO_FICHAJE=true`.
* `created_at` (TIMESTAMP)
* `UNIQUE(empleado_id, fecha)`
* `CHECK (hora_salida IS NULL OR hora_llegada IS NOT NULL)`: no salida sin entrada.
* `CHECK (hora_salida IS NULL OR hora_salida > hora_llegada)`.

#### 7. `feriados`
Un día o rango (el rango se expande a N filas, una por día).
* `id` (INT, PK, AI)
* `fecha` (DATE, UNIQUE, NOT NULL)
* `motivo` (VARCHAR(150), NOT NULL)
* `creado_por_usuario_id` (INT, FK -> `usuarios.id`, NOT NULL)
* `created_at` (TIMESTAMP)

#### 8. `vacaciones_empleado`
* `id` (INT, PK, AI)
* `empleado_id` (INT, FK -> `empleados.id`, NOT NULL)
* `fecha_inicio` (DATE, NOT NULL)
* `fecha_fin` (DATE, NOT NULL)
* `motivo` (TEXT, NULLABLE)
* `aprobado_por_usuario_id` (INT, FK -> `usuarios.id`, NOT NULL)
* `created_at` (TIMESTAMP)
* `CHECK (fecha_fin >= fecha_inicio)`: sin solape mismo empleado (validación backend).

#### 9. `pases_previos` (autorización anticipada fuera de margen)
* `id` (INT, PK, AI)
* `empleado_id` (INT, FK -> `empleados.id`, NOT NULL)
* `fecha` (DATE, NOT NULL)
* `motivo` (TEXT, NOT NULL)
* `creado_por_usuario_id` (INT, FK -> `usuarios.id`, NOT NULL)
* `created_at` (TIMESTAMP)
* `UNIQUE(empleado_id, fecha)`

#### 10. `logs_auditoria`
* `id` (INT, PK, AI)
* `usuario_id` (INT, FK -> `usuarios.id`, NULLABLE, NULL = kiosco)
* `accion` (ENUM('LOGIN','CREAR_EMPLEADO','DESACTIVAR_EMPLEADO','REACTIVAR','CREAR_REGLA','JUSTIFICAR','CREAR_FERIADO','CREAR_VACACION','CREAR_PASE'), NOT NULL)
* `tabla_afectada` (VARCHAR(50), NULLABLE)
* `registro_id` (INT, NULLABLE)
* `detalle` (JSON, NULLABLE)
* `ip` (VARCHAR(45), NULLABLE)
* `created_at` (TIMESTAMP)

### 2.2. Vista `v_asistencias_diarias` — por qué existe
FERIADO, VACACIONES y FALTA sin marcaje no existen como fila física. Para no crear filas falsas cada noche, la vista es una consulta guardada (no tabla) que proyecta virtualmente:
1. Hay fila en `asistencias` -> muestra lo real.
2. Sin fila y `fecha IN feriados` -> `FERIADO`.
3. Sin fila y `fecha BETWEEN vacaciones` -> `VACACIONES`.
4. Sin fila y Lun-Vie laborable -> `FALTA`.
5. Fin de semana no feriado -> se excluye. `activo=FALSE` -> excluido.

| Funcionalidad | ADMIN | RRHH | GERENTE | COORDINADOR |

## 4. Requisitos Funcionales (detalle)

### Módulo 1: Autenticación y Kiosco
* **RF-1.1:** Cuentas prediseñadas: por cada gerencia un Gerente y un Coordinador, más Administrador y RRHH globales.
* **RF-1.2:** Solo usuario Administrador restablece usuarios/claves.
* **RF-1.3:** Clave inicial obliga a cambio en primer ingreso.
* **RF-1.4:** Kiosco público sin sesión, credencial propia solo-fichaje, 1 req/s por equipo.

### Módulo 2: Personal
* **RF-2.1:** Solo usuario Administrador y usuario RRHH registran empleados (documento único, nombres, cargo, gerencia).
* **RF-2.2:** Cámara siempre activa mientras la pantalla de registro está abierta, con vista previa permanente hasta capturar firma 128 flotantes.
* **RF-2.3:** Baja lógica/reactivación con confirmación + log. Baja no ficha ni genera FALTA, conserva historial.

### Módulo 3: Kiosco Entrada/Salida
* **RF-3.1 Entrada:** sin fila hoy -> crea con hora servidor + snapshot regla vigente (`MAX(fecha_inicio_vigencia) <= hoy`). `<= limite` = A TIEMPO, `> limite` dentro de margen = TARDE.
* **RF-3.2 Salida:** con entrada sin salida -> registra salida. `< referencia` = TEMPRANO, `>= referencia` = COMPLETADO. Calcula extras.
* **RF-3.3 Duplicado:** con entrada+salida -> *"Ya ha registrado su entrada y salida por hoy"*.
* **RF-3.4 Orden:** sin entrada no hay salida. Salida > llegada (validado).
* **RF-3.5 Confirmación 3s:** nombre, gerencia, tipo, estado, rostro en memoria (`canvas`, no persistido), + extras.
* **RF-3.6 Excepciones:** no registrado = aviso 10s con reintentar (fondo sigue escaneando); >1 rostro = aviso 5s *"Solo una persona"*, descarta intento.
* **RF-3.7 Liveness rebajado:** parpadeo + delta movimiento + `d < 0.5` + rate-limit. Sin sensor profundidad.
* **RF-3.8 Cooldown 30 min por empleado:** tras éxito no puede remarcar hasta 30 min (muestra cuenta regresiva). Kiosco sigue atendiendo a otros.
* **RF-3.9 Extras:** normal = salida - referencia (si >0); FERIADO/VACACIONES trabajado = salida - llegada; sin salida = 0.
* **RF-3.10 Margen 60 min + pase:** fuera de `limite + margen` sin `pases_previos` hoy -> rechaza (*"Fuera de horario, requiere autorización"*), queda FALTA proyectada. Con pase -> entra y queda JUSTIFICADO con horas reales. En FERIADO/VACACIONES con marca: `estado_entrada='A TIEMPO'` forzado (no se evalúa tardanza), extras = jornada completa.
* **RF-3.11 Comparación local:** kiosco descarga descriptores y compara local (uso local, riesgo aceptado).

### Módulo 4: Horarios
* **RF-4.1:** Administrador y RRHH definen entrada, salida referencia y margen (default 60) con vigencia futura.
* **RF-4.2/4.3 Inmutabilidad:** rige hacia adelante; snapshot en cada fila impide alterar pasado.

### Módulo 5: Feriados
* **RF-5.1:** Día único o rango + motivo. Rango se expande a filas diarias. Sin duplicar fecha.
* **RF-5.2:** Sin marca = FERIADO (no falta, no justificable). Con marca = asistencia + extras totales.

### Módulo 6: Vacaciones
* **RF-6.1:** Por empleado inicio/fin + motivo + aprobador, sin solape.
* **RF-6.2:** Sin marca = VACACIONES. Con marca = asistencia + extras totales.

### Módulo 7: Ausencias y justificativos (incluye pase previo)
* **RF-7.1:** Activo sin marca en Lun-Vie no feriado/vacación = FALTA (incluye bloqueado por margen).
* **RF-7.2:** Sobre FALTA/TARDE: adjunta URL + observaciones -> JUSTIFICADO + log. Si no existía fila -> UPSERT con `hora_llegada=NULL`.

### Módulo 8: Panel e histórico
* **RF-8.1:** Filtros por fechas, gerencia, estado (A TIEMPO, TARDE, FALTA, JUSTIFICADO, FERIADO, VACACIONES, TEMPRANO, COMPLETADO) + extras.
* **RF-8.2:** Recorte por rol.
* **RF-8.3 Ficha clicable:** todo nombre es enlace a histórico con datos, cronología filtrable, totales (tardes, faltas, justificadas, extras), respaldos y autorizador.

### Módulo 9: Auditoría
* **RF-9.1/9.2:** Log de logins, personal, bajas, reglas, feriados, vacaciones, pases, justificativos. Solo ADMIN/RRHH consultan.

## 5. Requisitos No Funcionales
* **RNF-1:** Tiempo corto por persona (meta 1.5s, no bloqueante, 100 emp. max, O(N) aceptado).
* **RNF-2:** Umbral `d < 0.5` anti falsos positivos.
* **RNF-3:** Sin fotos por defecto (solo vector irreversible); thumbnail 150px solo si `GUARDAR_FOTO_FICHAJE=true` con retención y consentimiento.
* **RNF-4:** HTTPS obligatorio para `getUserMedia`; Bcrypt >=12; sesiones con caducidad; kiosco restringido.
* **RNF-5:** Rate-limit 1/s por kiosco.
* **RNF-6:** Hora servidor `UTC-4` local; SQL ACID (PostgreSQL / MySQL InnoDB).

* `FeriadosController` — día/rango.
* `VacacionesController` — asignación anti-solape.

* `AuditoriaController` — logs.
